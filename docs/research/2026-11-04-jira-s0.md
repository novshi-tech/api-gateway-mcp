# Jira のコネクタの S0（実物で確かめる）

2026-11-04。`docs/adr/0034` の段取り S0。ゲートウェイの `jira`（Atlassian の OAuth 2.0 3LO、組み込みの接続先）に本人がつないだ接続で、本体が使う予定の口を実物で叩いた。
本体の同意（ゲートウェイの OAuth のトークン）ではなく、本人の短命トークン（`issue_token`）で呼んだ。上流への呼び出しは同じゲートウェイの同じ Atlassian のアプリを通るので、Jira の振る舞いは同じ。

## ゲートウェイに Jira を足したときにつまずいたこと

- Atlassian の developer console のアプリに **User identity API の `read:me`** を足していないと、同意の画面で「requested ... scopes that have not been added to the app」になる。Jira API のスコープは **Classic scopes** のタブで付ける（ゲートウェイは classic の名前で頼む）
- api-gateway-mcp の README の Jira の節には両方とも書いてある（User identity API と `read:me`）。見落としやすいので、手順のほうで強調するとよい

## 読み取り（すべて 200）

| 口 | 結果 |
| --- | --- |
| `GET /oauth/token/accessible-resources` | サイトが 1 つ。`id`（cloudId）・`url`・`name`・`scopes`（`manage:jira-webhook`・`read:jira-user`・`read:jira-work`・`write:jira-work`。`read:me` は別の API なのでここには出ない） |
| `GET /rest/api/3/myself` | `accountId`・`accountType: atlassian`・`displayName`・`timeZone: Asia/Tokyo`・`emailAddress`。リストでのアイデンティティは `accountId` |
| `GET /rest/api/3/search/jql`（GET で通る） | 応答は `issues`・`nextPageToken`・`isLast`（`total` はない）。`nextPageToken` を付けて GET でページを送れる |
| 相対時刻の JQL | `updated >= -30d`・`updated >= -120m` とも通る。`ORDER BY updated ASC` も通る |
| `fields=comment` | 検索の応答に入るコメントは **最大 20 件**（`total` は 35 でも `comments` は 20）。コメントは課題ごとに別に取る |
| `GET /rest/api/3/issue/{key}/comment?orderBy=-created` | `startAt`・`maxResults`・`total`・`comments`。コメントは `id`・`created`・`updated`・`author.accountId`・`author.accountType`・`body`（ADF） |
| `GET /rest/api/3/webhook` | 0 件（`values: []`）。この口は読める |

量の目安: 既定の範囲（`assignee = currentUser() OR reporter = currentUser() OR watcher = currentUser()`）で、30 日に更新された課題は 20 件。5 分ごとの差分は、ほとんど 0〜1 件になる。

写しの項目は全部取れる: `status.name`（ステータス名）、`status.statusCategory.key`（`done` で完了）、`assignee.accountId`、`duedate`（`YYYY-MM-DD`）、`summary`。`updated` はオフセット付き（`+0900`）なので UTC にそろえる。

## 動的 Webhook（直樹の許可で登録して試し、終わってから消した）

`POST /rest/api/3/webhook`（ゲートウェイの `jira` の本人の接続。スコープ `manage:jira-webhook`）。送り先は `https://murmur.urban-b.workers.dev/webhooks/jira/s0-<ランダムな秘密>`（本体にはまだ受け口がないので 404 を返す）。

| 試したこと | 結果 |
| --- | --- |
| `jqlFilter: project = SPW` | 登録できた（`createdWebhookId`）。`expirationDate` は登録の 30 日後 |
| `jqlFilter: assignee = currentUser() OR watcher = currentUser()` | **`Clause watcher is unsupported`**。`watcher` は jqlFilter で使えない |
| `jqlFilter: assignee = currentUser() OR reporter = currentUser()` | 登録できた |
| `jqlFilter: assignee = <accountId>` / `issuekey IN (SPW-2040)` | どちらも登録できた |
| 別の URL でもう 1 つ登録 | **`Only a single URL per user is allowed to be registered via REST API`**。URL は本人（ゲートウェイの Atlassian のアプリ × ユーザー）ごとに 1 つ。同じ URL なら Webhook はいくつでも足せる |
| URL のパスに秘密を入れる | そのまま届いた。パスの秘密で受け口を守れる |
| 届いたか | 本人が担当で起票した完了済みの課題（ウォッチャーは本人だけ）にコメントを 1 件書くと、2 通の POST が届いた（`project = SPW` の Webhook の `comment_created` と `jira:issue_updated` と思われる）。`User-Agent: Atlassian Webhook HTTP Client`、`Authorization` ヘッダーあり、`x-atlassian-webhook-identifier`・`x-atlassian-webhook-flow` あり |
| 後片付け | テストのコメントを消し（204）、Webhook を 4 つとも消した（`DELETE /rest/api/3/webhook`、202。一覧は 0 件） |

見られなかったこと: Workers のログは `Authorization` の中身を伏せ、本文を残さないので、JWT の鍵と本文（`matchedWebhookIds` など）は見ていない。受け口を作ったら、本文の形を記録して確かめる。
このセッションのプロキシは `wrangler tail` の WebSocket を通さない。届いたかは Cloudflare の API（Workers のログの検索 `workers/observability/telemetry/query`）で見た。

## 実装を出してからの確認（2026-11-04 後半）

本体（0034 の S1・S2）を UBS に出し、直樹が `POST /connections/jira` でつないだ（同意は Outlook と共有なので許可の画面なし）。

- Webhook は 1 つだけ登録された（jqlFilter は `watcher` を外した `assignee = currentUser() OR reporter = currentUser()`、期限は 30 日後）
- 直樹が古い完了済みの課題にコメントすると、`comment_created` の通知 → 8 秒後に写し（完了・担当は本人）とコメントのシグナル（本人から、こちら → 宛先なし）でスレッドになった。誰の番は「なし」（ソースで完了）
- **届いた本文の形**（ログの `jira_webhook`。S0 の残り）:
  - `comment_created`: キーは `comment`・`eventType`・`issue`・`matchedWebhookIds`・`timestamp`・`webhookEvent`
  - `jira:issue_updated`: キーは `changelog`・`issue`・`issue_event_type_name`・`matchedWebhookIds`・`timestamp`・`user`・`webhookEvent`
  - `matchedWebhookIds` は登録した Webhook の ID（`[5]`）。本体は中身を使わないので、このまま
- 届いた JWT の鍵は見ていない（本体は検証しない。0034 の未決 3）

## 0034 への反映

- Webhook の URL は本人ごとに 1 つ（`/webhooks/jira/<本人ごとの秘密>`）。どのデータソースの通知かは、同じ本人のデータソースが 1 つならそれ、複数ならすべて取り直す（通知はヒントなので、多めに取り直しても台帳は変わらない）
- `watcher` は jqlFilter で使えない。Webhook の jqlFilter は、範囲の JQL のうち使える節だけにするか、`project IN (...)` のように広めにして、取り直しの JQL で絞る
