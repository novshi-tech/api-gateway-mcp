# Jira のコネクタの S0（実物で確かめる）

2026-11-04。`docs/adr/0034` の段取り S0。ゲートウェイの `jira`（Atlassian の OAuth 2.0 3LO、組み込みの接続先）に本人がつないだ接続で、本体が使う予定の口を実物で叩いた。
本体の同意（ゲートウェイの OAuth のトークン）ではなく、本人の短命トークン（`issue_token`）で呼んだ。上流への呼び出しは同じゲートウェイの同じ Atlassian のアプリを通るので、Jira の振る舞いは同じ。

## ゲートウェイに Jira を足したときにつまずいたこと

- Atlassian の developer console のアプリに **User identity API の `read:me`** を足していないと、同意の画面で「requested ... scopes that have not been added to the app」になる。Jira API のスコープは **Classic scopes** のタブで付ける（ゲートウェイは classic の名前で頼む）
- api-gateway-mcp の README の Jira の節には両方とも書いてある（User identity API と `read:me`）。見落としやすいので、手順のほうで強調するとよい

## 読み取り（すべて 200）

| 口 | 結果 |
| --- | --- |
| `GET /oauth/token/accessible-resources` | サイトが 1 つ。`id`（cloudId）・`url`・`name`・`scopes`（`manage:jira-webhook`・`read:jira-user`・`read:jira-work`・`write:jira-work`。`read:me` は別の API なのでここには出ない） |
| `GET /rest/api/3/myself` | `accountId`・`accountType: atlassian`・`displayName`・`timeZone: Asia/Tokyo`・`emailAddress`。リストでのアイデンティティは `accountId` |
| `GET /rest/api/3/search/jql`（GET で通る） | 応答は `issues`・`nextPageToken`・`isLast`（`total` はない）。`nextPageToken` を付けて GET でページを送れる |
| 相対時刻の JQL | `updated >= -30d`・`updated >= -120m` とも通る。`ORDER BY updated ASC` も通る |
| `fields=comment` | 検索の応答に入るコメントは **最大 20 件**（`total` は 35 でも `comments` は 20）。コメントは課題ごとに別に取る |
| `GET /rest/api/3/issue/{key}/comment?orderBy=-created` | `startAt`・`maxResults`・`total`・`comments`。コメントは `id`・`created`・`updated`・`author.accountId`・`author.accountType`・`body`（ADF） |
| `GET /rest/api/3/webhook` | 0 件（`values: []`）。この口は読める |

量の目安: 既定の範囲（`assignee = currentUser() OR reporter = currentUser() OR watcher = currentUser()`）で、30 日に更新された課題は 20 件。5 分ごとの差分は、ほとんど 0〜1 件になる。

写しの項目は全部取れる: `status.name`（ステータス名）、`status.statusCategory.key`（`done` で完了）、`assignee.accountId`、`duedate`（`YYYY-MM-DD`）、`summary`。`updated` はオフセット付き（`+0900`）なので UTC にそろえる。

## まだ確かめていないこと

- **動的 Webhook の登録**（`POST /rest/api/3/webhook`）: URL の制約（アプリごとに 1 つか、パスに秘密を入れられるか）、`jqlFilter` に `currentUser()` が使えるか、届く本文と `Authorization` の JWT、30 日の寿命と延長
