# 0003 ゲートウェイから伝搬されるユーザー識別の形式

- 状態: 仮決め（ゲートウェイ側の仕様が来たら合わせる）
- 関連: 計画「認可の接続の形 (B)」「ステップ 1 のトークン検証: 本体は署名付きで伝搬された sub を検証する」

## 背景

(B) では本体はゲートウェイの上流サービスとして登録され、署名付きで伝搬されたユーザー識別（sub）を受け取る。
このセッションではゲートウェイのリポジトリと上流サービスの登録方法を参照できなかったため、形式を仮に決めて実装した。

## 決定（仮）

- ヘッダ `x-murmur-identity` に compact JWS（`alg: EdDSA`、Ed25519）を載せる
- クレーム: `sub`（ゲートウェイの User ID。IdP の subject ではなく、アカウントリンクで束ねた User の ID）、
  `aud`（`murmur`）、`iat`、`exp`（寿命は 1 時間まで、時計のずれは 30 秒まで許す）、`iss`（任意）
- 本体が持つのはゲートウェイの公開鍵（`GATEWAY_IDENTITY_PUBLIC_KEY`、JWK）だけ。共有秘密・API キーは持たない
- 検証は `src/auth/identity.ts`（署名）と `src/auth/claims.ts`（クレーム、純関数）

## ゲートウェイ側に必要な改修（ステップ 1 の成果物のうち、このリポでは未着手）

- 上流サービスの認証方式に「ユーザー識別の伝搬」を追加し、上の形式で sub に署名して Service Binding 越しに渡す
- 本体を上流サービスとして登録し、スタンド用のスキル（`docs/stand/skill.md`）を配る

## 未決

- ゲートウェイ既存の署名方式・鍵の配り方（JWKS エンドポイントか、固定の公開鍵か）に合わせて置き換える
