# 0027 オーケストレータのスタンドが実行のスタンドを束ねる。ボールは本人のまま

- 状態: 案（2026-10-29、直樹とのディスカッション）。Murmur の本体は変えない。スタンドの側の約束を書く
- 関連: 0012（本体は外に書かない、何も実行しない。着地: boid は開発のスタンド）、0008（要約を書くのはスタンド）、0014（個人のメモ）、0026（自分専用の Murmur は作らない）、H7、H8
- 発端: novshi-tech/boid の `docs/plans/split-and-shrink.md` §3・§4

## 背景

0012 の「着地」で、boid は開発タスクを実行するスタンドの 1 つになり、Cowork は事務のスタンド、boid は開発のスタンド、とした。振り返り（`docs/retrospective-v2.md` 2 の 3）では「boid 本体をどう縮退させるかは boid の側の判断」で持ち越していた。

boid の側の議論（2026-10-29）で、boid には workspace・sandbox・job だけを残すことになった。boid の task・状態機械・親子タスク・「走りながら人に聞く」（`task ask`）はなくなる。boid の card で分かったのは、タスクの種類や親子関係が「タスクの実行 → judge → 次のタスクの提案」のループで相当程度代用できること。そのループを誰が回すかが問いになった。

一度、ask を Murmur に書いてボールを本人に戻す形を考えたが、それには Murmur にエージェントの身元が要る（エージェントが本人のトークンで書くと、本人が本人に聞いていることになる）。

## 決定（案）

### 1. エージェントは全部スタンドで、スタンドは本人の代理。ボールは本人のまま

- Murmur から見ると、エージェントは全部スタンドで、スタンドは本人の代理。スタンドが動いている間も、エージェントが質問してきても、**ボールは本人から動かない**
- Murmur にエージェントの身元（エージェントの Party、エージェントの番）は足さない。誰の番かは今のとおり持ち主の操作と構造で決まる（H8）

### 2. オーケストレータ役のスタンドを置く

- **オーケストレータ**は、実行のスタンド（boid の job で動くコーディングエージェントなど）を起動・監視し、結果を judge し、次の一手を考え、必要なら人に質問を返すスタンド
- オーケストレータは実行しないので、コーディングエージェントである必要がない。Cowork でも、ほかのモデルのチャットでもよい
- 新しいプロダクトではなく、スキルで実現する（Murmur のスキルの隣に、boid の job を扱うスキルを足す）
- 起こし方は、タスクごとに起こしてそのタスクを見張らせるのが基本。定期実行で、実行できそうなタスクを見つけて回す形もある

### 3. 実行のスタンドは Murmur を知らない。オーケストレータが中継する

- boid の job は Murmur を読み書きしない。job は結果（要約・質問・成果物）を boid に返して終わり、オーケストレータがそれを読んで、人と Murmur の間を中継する
- そのため、boid と Murmur は直接つながらない。オーケストレータは、ゲートウェイ経由で Murmur（今のまま Service Binding）と boid（ゲートウェイの `identity` の接続先）の両方を呼ぶ

```
            人
            ▲│ 質問 / Go
            │▼
   オーケストレータ（スキル）
     │ 読む・記録する        │ job の起動・状態・結果
     ▼                       ▼
   Murmur ◀── ゲートウェイ ──▶ boid（workspace・sandbox・job）
```

- 外に送ったもの（PR を作った、Jira に書いた）は、今までどおり送ったスタンド（またはオーケストレータ）が `record_sent` で記録する（0012 のまま）

## 本体への影響

- 本体のコード・イベント型・API は変えない
- スキルの文面に、スタンドは本人の代理で、ボールを動かさないことと、オーケストレータの役割を書く

## 代案

- **ask を Murmur に書き、エージェントの番にする**: エージェントの身元を Murmur に足すことになり、誰の番かが持ち主の操作と構造だけで決まらなくなる（0013）。採らない
- **実行のスタンドが直接 Murmur を読み書きする**: 実行のスタンドごとに Murmur の接続とスキルが要り、boid の job のように Claude 以外のハーネスで動くものにも Murmur の約束を持ち込むことになる。中継をオーケストレータ 1 か所にまとめる

## 未決

1. 人がチャットにいないときに、オーケストレータの質問をどこに置くか。個人のメモのスレッドに書く（次の巡回で見える）か、オーケストレータの定期実行がまとめて知らせるか
2. 実行のスタンドの結果を、Murmur のどこに綴じるか（個人のメモのスレッドのタイムラインか、成果物のスレッドとのリンクか）
