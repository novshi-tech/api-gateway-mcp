# 0025 Microsoft 365 グループのメールボックスは、購読者にした共有メールボックスで読む

- 状態: 採用（2026-10-29、直樹）。実装は後回し（グループのメールボックスを取り込むときにやる）。変更通知の検証は、本人の箱（0024 の決定 3）で先に行う
- 関連: 0024（決定 4: 共有の箱はアプリの権限で読み、RBAC for Applications で絞る。この ADR はその前提を保つための手順）、0012（外には何も書かない）、0013（共有のデータソースは組織の資格情報）、0020（1 デプロイ = 1 チーム）

## 背景

0024 は、チームの共有の連絡先を「共有メールボックス」と見て、アプリの権限（Exchange の役割 `Application Mail.Read`）を RBAC for Applications の管理スコープで読ませる箱だけに絞ることにした。

実際には、チームの共有のアドレスが共有メールボックスではなく、Microsoft 365 グループ（グループのメールボックス。`RecipientTypeDetails` が `GroupMailbox`）のことがある。この場合、`Set-Mailbox` では見つからず、0024 の手順はそのまま使えない。Graph でグループのメールを読むのは `/groups/{id}/conversations`（スレッドと投稿）になる。

議論の途中で、まずはアプリの権限 `Group.Read.All` でグループを直接読む案が出た（直樹）。公式ドキュメントを調べて、次のことがわかった。

## 調べたこと（2026-10-29、Microsoft Graph の公式ドキュメント）

- 変更通知: グループの会話（`groups/{id}/conversations`）は、委任（職場のアカウント）の `Group.Read.All` だけで作れる。**アプリの権限では作れない**（Create subscription の権限の表で Application が Not supported）
- delta: 会話・スレッド・投稿には delta がない（Delta query overview の一覧にない）
- 読み取りの最小の権限は `Group-Conversation.Read.All`（委任・アプリとも）。どちらにしてもテナントのすべてのグループの会話に届き、Exchange のスコープでは絞れない

グループを直接読むと、0024 の「通知はヒントで、正は delta」と「アプリの権限は読ませる箱だけに絞る」がどちらも成り立たない。

## 決定

1. グループのメールボックスを取り込むときは、共有メールボックスを 1 つ作り、そのグループのメンバーかつ購読者にする。グループに届いたメールのコピーが共有メールボックスの受信トレイに入る
2. 本体はその共有メールボックスを、0024 の決定 4 のとおり読む（アプリの権限、RBAC for Applications のスコープ、変更通知と delta）。本体とゲートウェイには、グループのための作りを足さない
3. 管理者の作業はグループごとに 1 回（共有メールボックスを作り、メンバー・購読者に足し、スコープの印を付ける）

## 代案

- A. アプリの権限 `Group-Conversation.Read.All` でグループを直接読み、Cron の見回りで新しいものを取る: 通知も delta もないので取り込みの作りが 0024 とは別に 1 つ増え、テナントのすべてのグループの会話に届く
- C. メンバーの本人の権限（委任の `Group.Read.All`）で通知を受ける: 管理者の同意が要り、その人がメンバーから抜けると止まる

## 実物で確かめること（取り込むとき）

- 共有メールボックスをグループのメンバー・購読者にできるか
- グループのエイリアス宛てを含め、届いたメールのコピーが共有メールボックスに入るか。グループの中の返信もコピーされ、In-Reply-To でスレッドがつながるか
