# 0004 投影の保存の仕方

- 状態: 採用（プロトタイプ限り）
- 関連: H1、計画「Neon: イベントストアと投影」「パフォーマンスは今回は度外視」

## 決定

- イベントは `events(tenant_id, seq)` を主キーにした append-only のテーブル。追記は「期待する最後の seq」を渡す楽観ロックで、
  競合したらシェルが読み直してコアの判断からやり直す
- 投影（tasks / signals / derivations / task_links / timeline / ignore_log と索引）は、fold の結果を JSONB で行ごとに置く。
  書き込みのたびにテナント分を入れ替える。`projection_meta.last_seq` より後のイベントがあれば、読み出し時に追いつく
- 投影はいつでも消してイベントから作り直せる（`MurmurService.rebuild`、H1 のテスト）

## トレードオフ

- 書き込みごとにテナント全体を入れ替えるので、件数が増えると遅い。本格展開時は差分の upsert とクエリ側の SQL 絞り込みに替える。
  実データでの試用（0007）では、つないですぐにここが詰まる見込み（0007「量の見通し」の 2）
- 可視性はクエリ層の純関数で強制している（0001）。SQL の WHERE で絞る形にしても、Viewer の導出と判定はコアに残す
