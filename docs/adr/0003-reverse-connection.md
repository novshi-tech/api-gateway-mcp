# 0003 boid を接続先にする。手元のサービスへは逆向きの接続で届く

- 状態: 案(2026-10-29、直樹とのディスカッション)。決定 1 はゲートウェイのコードを変えずにできる。決定 2 は構想
- 関連: [0001](0001-absorb-boid-gateways.md)、[background-access.md](../background-access.md)、README の `identity` の認証方式
- 発端: novshi-tech/boid の `docs/plans/split-and-shrink.md` §4

## 背景

縮退後の boid は、workspace・sandbox・job だけを持つ実行環境になる。job を起動して、監視し、結果を judge し、人に質問を返すのは、オーケストレータ役のスタンドになる。オーケストレータは実行しないので、Cowork でも ChatGPT でも Claude Code のクラウドセッションでもよい。オーケストレータは、このゲートウェイ経由で boid の job の API を呼ぶ。

boid は手元のマシン(LAN の中)で動くので、Murmur のように Service Binding で結ぶことはできない。ゲートウェイから boid に届く経路が要る。

## 決定(案)

### 1. boid を `identity` の接続先として登録する

```jsonc
"boid": {
  "display_name": "boid",
  "base_url": "https://boid.example.com/api",
  "auth": { "type": "identity", "audience": "boid" }
}
```

- ゲートウェイは、サインイン中のユーザーの ID を Ed25519 で署名した JWT を送る。boid は `https://<ゲートウェイ>/.well-known/jwks.json` で検証する。Murmur と同じ仕組みで、boid に新しい認証の仕組みは要らない
- `identity` は Service Binding がなくても `base_url` に送れるので、**最初は boid の API を Cloudflare Tunnel で公開し、その URL を `base_url` にする**。ゲートウェイのコードの変更は要らない
- boid の API は「サンドボックスの中で任意のコードを走らせる口」になる。boid の側で、ゲートウェイの JWT がないリクエストは全部はじき、受け付ける `sub` を設定で絞る

### 2. 逆向きの接続(WebSocket モード、構想)

手元のサービスのほうからゲートウェイにつなぎに行き、ゲートウェイが中継する。

- 手元のサービス(boid の daemon など)が、ゲートウェイの Durable Object に WebSocket の接続を張りっぱなしにする。ゲートウェイは、その接続先へのリクエストを WebSocket に載せて中継する
- 手元に外からの入口を開けなくて済むので、Tunnel より攻撃される面が小さい。セキュリティの面でもこちらが強い
- **boid 専用にしない**。汎用の「逆向きの接続先」として作る。接続先の定義の 1 種類にし、中継の動き(ヘッダーの注入、ボディの素通し、操作ログ)は REST と同じものを使う。ゲートウェイは HTTP と OAuth2 だけを知る、という性格を崩さない
- 汎用にすると、LAN の中のサービスへのトンネルとして使える。普通のチャットや Cowork から、LAN の中のサービスを叩けるようになる

## 条件・リスク

- **逆向きの接続は「チャットから LAN の中に入れる口」になる**。どの接続先を逆向きにしてよいか、誰が使ってよいかは管理者が決める。逆向きの接続先は管理画面で管理者だけが登録でき、手元の側がつなぎに来るときの資格(接続先ごとのシークレットなど)も管理者が発行する
- 手元のサービスの側は、届いたリクエストを自分の範囲に絞る(boid なら job の API だけ)。逆向きの接続を任意のホストへの中継にしない
- オーケストレータを通る結果は、オーケストレータのアカウントの Claude に入る。顧客向けの workspace の job の結果をメインのアカウントのオーケストレータが読むとき、何を返すかは boid の側の job の結果の約束で絞る

## 代案

- **boid を Cloudflare の Worker にする**: boid の価値は手元の実行環境(コンテナ、workspace の永続化)にあり、Worker にはできない
- **Tunnel だけで済ませる**: 最初はこれで始める。手元に入口を開けること、Tunnel の設定が手元ごとに要ることが気になったら、決定 2 に進む
